# Maintune v0.1.0-preview.2

`v0.1.0-preview.2` is a Preview release centered on Plugin API v1. It keeps the existing deterministic Controller, Owner Gate, GitHub maintenance workflows, runtime controls, and self-hosted deployment model.

## Plugin API v1

- Install validated local Maintune Plugin Packages (`.mtp`) without a marketplace.
- Enable, disable, and reload plugins while preserving configuration and plugin data.
- Run each plugin in an independent Python environment and process so dependency or process failures do not crash Maintune Core.
- Enforce declared capabilities such as `event.subscribe`, `task.read`, and `owner_decision.submit`.
- Encrypt plugin secrets at rest, keep them masked in the API and WebUI, and redact them from logs and audit events.
- Render package-provided `README.md` files in a sanitized viewer without executing arbitrary HTML or JavaScript.
- Support acknowledged event delivery, reconnect, deduplication, replay protection, and short human-readable task references.
- Present a compact plugin management UI with lifecycle, runtime, connection, documentation, and settings actions.

## First external integration

The Maintune ↔ AstrBot integration is implemented as two independent Preview plugins using only Plugin API v1 and the versioned `maintune.astrbot.v1` bridge protocol:

- [Maintune AstrBot Bridge](https://github.com/mcxianyujun/maintune-plugin-astrbot)
- [AstrBot Maintune Bridge](https://github.com/mcxianyujun/astrbot-plugin-maintune)

The bridge forwards selected task, Pull Request, and CI events to AstrBot and accepts bounded status, task, and explicit Owner Decision requests. It does not expose Maintune administrator credentials, GitHub credentials, model keys, arbitrary shell access, or fuzzy natural-language approval.

## Preview boundaries

- Plugin API v1 and both bridge plugins remain **Experimental** and may evolve before a stable release.
- Windows 11 + Docker Desktop final real-machine validation remains pending.
- No prebuilt GHCR image is provided. Release bundles contain source and metadata only; users build the Runtime locally.
- Local Sandbox is a bounded execution environment, not a strong security boundary. Use Shipyard Neo for untrusted repositories.

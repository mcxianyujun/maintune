# v0.1.0 Stable Phase 0 — Ecosystem Audit

## Objective and baseline

Audit the released `v0.1.0-preview.3` ecosystem before changing product code. The isolated checkout starts at merge commit `866868f0f273d1cb3dc92604602e1b6595b8cf6e`, which is also the GitHub `main` HEAD checked through the read-only GitHub branch API on 2026-09-29. The existing development checkout contains unrelated changes and was left untouched. Phase 0 changes only this roadmap and report.

## Security and compatibility boundaries

- Keep third-party plugin imports limited to `maintune_plugin_sdk`; `maintainer.*` and internal database/Controller objects are not public APIs.
- Only `code_worker` currently receives plugin Agent Tools. Recommended agents do not automatically gain Tool access.
- Config secrets are encrypted and masked by Core; nested `secret: true` declarations are rejected in Preview 3. Plugin results and logs must not return secrets.
- Plugins cannot bypass deterministic Controller/Owner Gate decisions or obtain raw GitHub credentials. `pr.review` remains experimental and Core validates current PR head SHA on resume.
- Plugin signing, marketplace trust, remote runtime, Event Bus, Custom Tasks, ReviewProvider abstraction, streaming and automatic rollback remain outside v0.1.0 scope.
- The public GHCR image remains unavailable because the runtime dependency tree includes proprietary `lmnr-claude-code-proxy`; Stable readiness must not imply a redistributable image.

## Ordered implementation plan

1. **Developer Foundation:** package and validate the SDK independently; write an exact API reference and developer/migration guide; extract the existing minimal template without changing the Core runtime.
2. **Official AnySearch:** turn the tested in-tree example into its own versioned plugin package/repository, with explicit license, config/secret documentation, `.mtp` build and integration checks.
3. **MCP Review Example:** demonstrate the existing experimental workflow replacement/wait/resume/head-SHA contract through a plugin-owned MCP integration; do not put MCP credentials or protocol logic in Core.
4. **Stable RC:** freeze the API and official artifacts; run full backend, frontend, plugin, packaging, security, documentation and v1 compatibility gates; assess unresolved limitations before any Stable tag or deployment.

## Known limitations and next-phase readiness

Phase 0 is an audit, not a Stable compatibility declaration. The SDK distribution, official Template and AnySearch packages, MCP example and full Stable gates remain outstanding. Phase 1 can proceed on a separate feature branch without changing Preview tags or production.
